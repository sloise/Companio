# Companio workflow changes

The existing React/Laravel layout is retained. The local database migrations 2026_10_18_000001 (screening) and 2026_10_18_000002 (profile pictures) add fields without deleting records. Apply it with php artisan migrate when deploying another copy, then build the frontend with npm run build.

- New rescue records always start Awaiting Foster. Staff explicitly answer all care, behavior and household safety rules and confirm their assessment. Application and placement workflows control later statuses.
- Every match card shows all five rules. Each met rule contributes 20%. Applications require a minimum 60% compatibility; unmatched rules remain visible for shelter review and do not independently block eligibility. The server recalculates eligibility again before approval.
- Urgent is a staff-assessed time-sensitive welfare or shelter capacity need. A reason is mandatory for newly marked urgent pets; a deadline is optional. Best-match sorting uses urgency to break score ties. Urgent sorting prioritizes urgent pets then score. Urgency does not increase compatibility or bypass screening. Saved pets retain their existing priority within the chosen order.
- My profile shows account, contact, caretaker and household details. Saved personal and household edits have a seven-day cooldown and require admin re-screening under Applications > Home profile screening. Contact the shelter for urgent corrections. Existing profiles need review and may need missing contact fields completed. The questionnaire asks pet-free households about a future foster's time alone.
- Contact and household data are reused from the saved profile; applications preserve a snapshot. Changing the profile invalidates pending verification. Applications tied to an older profile must be withdrawn and submitted again.
- Applicants upload government ID and 2-5 home images. Applicants under 18 must also provide an adult co-signer's details, ID and declared consent. Staff validate the co-signer identity, age, contact and consent. Uploads alone do not establish identity.
- Files are stored under Laravel's private local disk and downloaded only through authenticated admin endpoints. Allow up to 4 MB per file and at least 32 MB total POST/upload capacity on the deployment server. The local PHP configuration permits 40 MB.
- Applicants request an interview or shelter visit before their foster start date. Admins confirm or adjust the appointment and notify the volunteer. Admins must record completed identity, home, emergency caretaker, appointment and applicable co-signer checks before approval. Date/time inputs use the browser timezone and are sent as ISO timestamps.
- Historical applications lacking documents remain visible but cannot be approved until volunteers submit a complete replacement. Current placements are retained. Admins can return/reclaim an active pet at any time; adoption confirmation is offered only for a formal adoption request. Ended placements cannot be reopened by status edits.
- Search, filters and sorting are grouped in the sidebar. Tour cards use free space beside the highlight; narrow screens reserve separate instruction and visible highlight areas. Cards stay inside the viewport and scroll internally if needed.

Validation: Laravel workflow tests (SQLite in memory), ESLint, Vite production build, and headless Chrome UI checks with mocked API responses at desktop, mobile and short viewports. Browser checks do not modify real account records.

Profile pictures can be uploaded, changed or removed from My profile. The server uses PHP GD (enabled locally) to validate and crop JPG/PNG/WebP uploads to a 320px square; photos also appear in the account menu. Cosmetic photo changes do not reset screening or household edit cooldowns.

Shelter Admin registration now collects the applicant name, email, password and private ID only; Shelter Name and Address have been removed. Pending and rejected applicants cannot sign in or access admin features. Super Admin alone can access Staff Requests, applicant ID previews, staff counts and staff-related notification data. The main dashboard shows only the latest three pending requests. Approve and Reject require confirmation, and rejection requires a reason. IDs open inline in a modal with image zoom or native PDF controls.

Rejected applicants can register again using their email. The previous rejected user row, ID, rejection reason and reviewer are preserved; its login email is replaced with a unique reserved address and its original email is retained for audit display. Old tokens and password-reset tokens are invalidated. A new registration always starts with fresh credentials and, for Shelter Admin applicants, a new pending review. Active and pending emails remain unique.

Animal records now include date of birth, health status, species-specific multiple vaccine records with vaccination and optional due dates, and spay/neuter status. Known birth dates calculate age on every response. Birth date is optional; Unknown enables optional estimated years (0?100) and months (0?11). An exact birth date takes precedence and clears estimates. Neither birth date nor estimate is required; new records display Age Unknown when both are absent. Estimates are recorded values and do not advance automatically. Migration 000005 converts legacy ages with explicit year/month units to structured estimates while preserving their original strings; ambiguous legacy age text is retained until edited. Mixed breed opens a text field with breed suggestions. Changing species clears vaccine records. Health records appear on the pet details page.

All document uploads have per-file removal that clears native file selections and previews. Profile picture uploads are staged until Save profile picture is clicked. The existing animal-photo removal is retained. Initial Full Name comes from registration and is read-only; the backend enforces the registered name on first setup. Later edits use the existing Edit Profile flow and seven-day cooldown. Philippine mobile inputs accept only 09XXXXXXXXX or +639XXXXXXXXX, normalize to the local format on the server, and compare normalized emergency/co-signer contacts. None in time-alone saves as 0 hours and participates normally in matching.

Deployment: run php artisan migrate in companio-api and npm run build in companio-frontend. The existing admin@companio.test Super Admin assignment is retained. On another installation, designate an existing approved admin with php artisan companio:super-admin trusted@example.com. No account is automatically promoted. Pending historical requests without IDs remain unapprovable until valid proof is securely collected.

Validation for this update: Laravel feature tests cover animal age and health persistence, species and date validation, retained rejected-email re-registration, profile name editing and initial locking, phone validation, zero-hours matching and role-scoped staff counts/notifications. Run php artisan test, npm run lint, npm run build and node tests/browser-workflow.cjs (from companio-frontend after building). Browser checks run in local headless Chrome with mocked APIs and never alter real user records.

Optional fields update: Address and Emergency caretaker full name have native placeholders, visible only while empty. Home profile screening defaults to None and may be submitted without notes; Comments reveals an optional text area. Laravel stores no notes for None and retains the existing role, profile-version and safety checks. Female animal statuses are Spayed, Not Yet Spayed and Unknown; Male statuses are Neutered, Not Yet Neutered and Unknown. With unknown sex, only Unknown is offered. Changing sex resets an incompatible selection, and Laravel rejects inconsistent pairs. The migration maps the previous status vocabulary to these values.

Vaccination dates may be empty or explicitly Unknown independently of birth date. Missing dates are saved as null in the existing vaccine JSON; the pet details page labels them Vaccination date unknown. Known vaccination dates cannot be in the future or before a known birth date, and a known due date cannot precede a known vaccination date. A due date remains required for Vaccination Due Soon. Vaccine selection never sets health status automatically.

Validation for optional fields: 40 Laravel tests (333 assertions), ESLint, production build, and headless Chrome checks passed. Coverage includes empty and estimated ages, known-date precedence, invalid estimates, sex/status consistency, optional vaccine dates, optional screening findings, placeholders, and prior registration, upload and role restrictions. Apply migration 2026_10_18_000005_add_estimated_animal_age when deploying another copy.

Important-action confirmations: the existing feedback modal is shared by animal creation/edit/deletion, home-profile setup/edits, saved profile-photo changes/removal, foster application submission/approval/rejection/reopening/withdrawal, home-screening approval/rejection, appointment confirmation/rescheduling, completed verification, Super Admin staff decisions, placement adoption/return/reclaim/continued fostering, volunteer adoption/return requests and their cancellation, account registration, and password resets. Dialogs name the affected person or animal and describe the outcome. Cancel/Escape sends no mutation; form drafts remain available. A shared synchronous guard blocks repeated action triggers while a confirmation or API request is pending. Backend failure leaves saved records and status unchanged and displays an error; success notifications, resets, navigation and refreshes follow successful responses.

Foster-application rejection now requires a reason of up to 500 characters, validated in Laravel and entered in the shared modal. Staff rejection retains its existing required reason (up to 2,000 characters). Home-screening findings remain optional as requested. Existing admin/Super Admin route middleware and placement/application ownership checks remain enforced. Laravel rejects a second open adoption/return request until the first is cancelled. Confirmation is a user-interface safeguard; authorization and validation remain independent server checks.

Searching, filtering, page/document viewing, choosing/removing unsaved files, bookmarks, notification reading, sign-in/sign-out and requesting a password-reset email remain lightweight actions without extra confirmation. Bookmark lists now update only after successful API writes. There are no archive or release controls in the existing site; current return/reclaim and placement transitions are covered.

Confirmation regression checks: run php artisan test, npm run lint, npm run build, node tests/browser-workflow.cjs and node tests/browser-confirmations.cjs. Run the browser scripts sequentially from companio-frontend; both use local headless Chrome and mocked APIs, without changing real records. The confirmation matrix exercises Cancel, backend failures, successful actions and repeated confirmation clicks across the affected roles. No new database migration is required for this update.

UI refresh: the Staff Requests ID preview was fixed and verified first. Its close button contained a literal question mark; it now uses an SVG X with an isolated, non-submit handler. Repeated opening/closing and Escape send no unrelated mutations. The ID API still returns private, no-store, inline documents with nosniff protection behind Super Admin middleware.

The existing teal identity is retained through shared typography, spacing, card, form, button, table, modal, focus and responsive navigation styles in polish.css. Decorative emojis are replaced by reusable SVG icons; historical notification decorations are removed from presentation. Forms retain native and Laravel validation and now show accessible local validation summaries, visible required-field cues, format examples and password visibility controls. Keyboard skip links, page announcements and scrollable record regions improve navigation. Existing confirmation guards and all role checks remain intact.

Corgi loading artwork comes from the user-supplied CorgiLoader JSX/CSS, with the original orange/cream palette and four sit/run/wiggle/happy SVG poses. Shared page, profile, staff, ID and notification loading states use a compact adaptation. Indeterminate loading uses CSS motion without a fake percentage or polling timer; numeric ARIA progress values are used only when actual progress is supplied. Reduced motion shows a static corgi. Save-data and low-core devices disable motion. Login has an optional, button-triggered corgi fetch interaction outside the form; it never accesses passwords or sends network requests. Password visibility and entered values are unaffected.

UI verification: browser-id-preview.cjs checks the priority modal fix; browser-ui.cjs checks desktop/phone layouts, accessible button names, emoji-free interface text, password controls, optional play and reduced-motion corgi loading. Local mocked-data screenshots are saved under companio-frontend/tests/artifacts. Run the browser checks sequentially. Existing browser-workflow.cjs and browser-confirmations.cjs continue to cover forms, uploads, roles and important-action confirmations. No database migration or additional package is required for the UI refresh.
